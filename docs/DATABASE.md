# Database

PostgreSQL is accessed only through Prisma. Primary keys on new tables will be UUIDs. Migrations in `apps/api/prisma/migrations` are the way schema changes reach a database.

## Implemented

### PlatformMetadata

| Column     | Type         | Notes                                      |
| ---------- | ------------ | ------------------------------------------ |
| id         | UUID         | Primary key, generated by Prisma           |
| key        | text         | Unique                                     |
| value      | text         | Short operational values only              |
| created_at | timestamp(3) | Set on insert. The application writes UTC. |
| updated_at | timestamp(3) | Maintained by Prisma                       |

Table name: `platform_metadata`.

The seed writes `platform.version = 0.1.0`. This table is not a general configuration store for conferences.

The health check runs `SELECT 1`. It does not read `platform_metadata`.

## Implemented in the account migration

Migration `20261010162537_auth_accounts`. Primary keys are UUIDs. Column names are snake_case.

| Table                       | Purpose                                                                                         |
| --------------------------- | ----------------------------------------------------------------------------------------------- |
| `users`                     | Email (unique), Argon2id `password_hash`, `platform_role`, `email_verified_at`, `mfa_enabled`   |
| `profiles`                  | One row per user (`user_id` primary key): name, affiliation, ORCID, URLs, disciplines, language |
| `sessions`                  | SHA-256 `token_hash` (unique), expiry, optional `revoked_at`                                    |
| `email_verification_tokens` | SHA-256 token hash, expiry, optional `used_at`                                                  |
| `password_reset_tokens`     | Same shape as verification tokens, shorter lifetime                                             |
| `email_outbox`              | Recipient, subject, template key, status. No message body and no token                          |
| `audit_logs`                | Actor, action, resource, JSON metadata. No passwords or raw tokens                              |

`platform_role` is `RESEARCHER` or `SYSTEM_ADMIN`. Profile `language` is `en` or `fr`. Outbox status is `PENDING`, `SENT`, or `FAILED`.

Migration `20261010173500_conferences` adds the conference boundary:

| Table                    | Purpose                                                                                |
| ------------------------ | -------------------------------------------------------------------------------------- |
| `conferences`            | Slug, visibility, publication status, review mode, payment flag, dates                 |
| `tracks`                 | Named tracks with a code unique inside one conference                                  |
| `deadlines`              | Submission, review, notification, camera-ready, and registration dates                 |
| `conference_templates`   | Plain-text templates keyed by kind and language                                        |
| `memberships`            | One role per user per conference: chair, administrator, committee, reviewer, or author |
| `conference_invitations` | Hashed one-time invitation tokens. The raw token is only in the email                  |

Migration `20261011171005_papers` adds `papers`, `paper_authors`, `paper_files`, and `paper_status_events`. `papers.public_id` is unique and null until submit. `paper_files` stores the object key and SHA-256, not the PDF bytes. `conferences.next_paper_number` increments when a paper is submitted.

## Planned model

The following groups are the target model. They are not migrated yet. Names may be refined when a phase implements them, and redundant tables will not be added just to match this list.

### Conference

- Conference, edition, track
- Membership with a conference-scoped role
- Deadlines, settings, templates

### Paper

- Paper with an immutable public identifier such as `CONF2027-0042`
- Authors, versions, files, status history, declarations

### Review

- Reviewer expertise, assignment, conflict
- Review round, review, scores, criteria

### After review

- Revision request and submission
- Scientific decision and decision letter
- Rooms, sessions, presentation assignments and evaluations
- Camera-ready submission, similarity report, copyright submission
- Registration and a manual payment record

### System

- Notification preferences beyond the account language
- File asset pointing at private object storage, not the file bytes

## Rules for later migrations

- Foreign keys and unique constraints enforce ownership and “one active assignment” style rules.
- Indexes follow the filters used by dashboards: conference, status, assignee, and deadlines.
- Critical transitions run in a transaction and append a history row in the same transaction.
- Audit rows must not contain passwords, raw tokens, or manuscript bytes.
